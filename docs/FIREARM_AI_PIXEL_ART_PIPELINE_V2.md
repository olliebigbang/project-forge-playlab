## 一句话说明

玩家只输入枪械名字。AI 认出它是什么、填写机制轴并画成品；Godot 只负责编译玩法和自动验收，不再拿程序方块枪冒充真正武器，也不问玩家“你想怎么打”。

## 实际流程

1. 名称解析 AI 把玩家原文翻译成严格身份卡，例如 M4A1 的常规步枪布局、可伸缩枪托、握把前弹匣、平顶导轨和对应射击轴。
2. Godot 根据这些轴制作一张隐藏结构骨架。它只告诉画图模型“枪托、握把、弹匣和枪口应该在什么关系上”，永远不展示给玩家。
3. FAL 上的 `fal-ai/gpt-image-1.5` 根据准确型号、身份特征和结构约束画一张透明背景成品图。
4. `fal-ai/image2pixel` 把成品图转为最多 24 色的硬边像素图，并清理锯齿和透明边缘。
5. Godot 统一缩放到 96×96，然后自动检查：
   - 是否真有透明 Alpha，且不是空图；
   - 是否只有有限色板；
   - 枪托、机匣、主握把、弹匣、支撑区和枪口是否可读；
   - 弹匣在握把前、后或握把内的位置是否符合布局；
   - 平顶导轨是否错误长成带封闭孔的提把；
   - 是否把隐藏方块骨架原样当成成品。
6. 不合格时，系统把具体失败项写回下一次画图提示并自动重画，最多两次。玩家不参与机制选择或结构验收。
7. 只有通过门槛的图才会标记 `finished_art=true` 和 `presentable_to_player=true`，再进入训练区。

## 为什么换掉纯 Godot 画枪

Godot 程序图适合做结构参照，但只能画出“长条、握把、弹匣”这类抽象块，玩家很难一眼区分 M4A1、95 式或 81 杠。现在 Godot 仍保留这套图作为隐藏的机器骨架和诊断证据；真正展示的是 AI 成品像素图。

## 身份和机制各由谁负责

- 玩家：只提供物件名字或草图身份。
- 语义 AI：判断是不是受支持的手持枪械，并填写封闭的结构轴和射击轴。
- 图像 AI：按照准确身份和结构轴画成品外观。
- Image2Pixel：只做像素化，不决定枪械身份或玩法。
- Godot：校验所有声明、编译射击行为、测真实 Alpha 结构并决定成品能否使用。

## 真实 M4A1 证据

第一轮 Ideogram 候选把 M4A1 画成固定枪托和提把的 M16 风格，自动门槛拒绝为 `FIREARM_VISUAL_TOP_RAIL_HAS_CARRY_HANDLE_LOOP`。之后身份绘制器改为提示服从更强的 GPT‑Image 1.5；真实候选显示可伸缩 M4 式枪托、平直上导轨、握把前弹匣和紧凑护木，并在修正“伸缩枪托不等于只能是 MP5 双导轨”的轴定义后通过同一门槛。

已接受证据目录：

`output/firearm-fal-live-v1-20260827/m4a1-gpt-image-accepted-01/`

其中包含原始透明图、远端像素化结果、96×96 成品、完整提示词、隐藏骨架、自动门槛指标和最终 handoff。

## 开发者启动

```powershell
.\scripts\run_open_identity_firearm_ai.ps1 -EnvFile "C:\path\to\.env"
```

`.env` 只读取 `ANTHROPIC_API_KEY`、`FAL_KEY` 或 `FAL_API_KEY`。密钥只留在启动进程环境中，游戏退出后恢复或清除；请求、图片、manifest 和日志都不写密钥。默认视觉模式是 `FAL_FIREARM`，会产生 API 费用。普通游戏启动仍不会偷偷调用付费接口。

## 当前边界

当前成品门槛覆盖弹匣供弹的手枪、常规步枪/卡宾枪/冲锋枪和无托步枪。左轮、管式或折管霰弹枪、弹链武器、发射器和坦克仍会被识别为未支持类别，不会硬塞进“普通步枪”模板。
