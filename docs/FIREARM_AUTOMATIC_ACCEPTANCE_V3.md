# 枪械自动身份与像素成品管线 V3

## 玩家看到的规则

玩家只输入枪械名称，例如“中国95式步枪”“M4A1”“81杠”或“92式手枪”。玩家不选择射击方式，也不负责确认画得像不像。AI 解析身份和机制轴，图像管线画武器，自动门禁决定是否可用。

坦克不是“大号枪械”，仍走独立载具域；当前手持枪械管线不会把坦克硬塞进步枪模板。

## 身份、玩法和画面怎样分工

1. 名称解析层把原文解析为封闭的枪械身份声明。
2. 机制轴决定射击玩法，例如半自动/自动、射速、后坐力、精度、换弹、射程和操控重量。
3. 视觉身份卡只描述外形，例如枪托、机匣上沿、弹匣、护木和易混淆型号；它明确没有玩法权限。
4. Godot 根据机制轴编译攻击行为，并生成一张只供机器使用的结构骨架。骨架不是玩家成品。
5. FAL 的 GPT‑Image 1.5 画透明侧视成品，Image2Pixel 把它限制为最多 24 色的像素图。
6. 两轮独立视觉检查必须一致认可准确型号和 96px 可读性。
7. Godot 再检查真实 Alpha、枪托/握把/弹匣/枪口位置、色板和隐藏骨架泄漏。
8. 两道门禁都通过后才写入版本化缓存并允许展示；失败则自动重画，不问玩家。

## 冷门或易混型号的参考图分支

纯文字容易把 81 杠画成普通 AK/56 式。因此 V3 支持由系统目录绑定“准确型号参考图”：

- 玩家和名称解析 AI 都不能提供网址，只能使用代码白名单中的参考编号。
- 桥接层下载参考图后核对固定 SHA‑256；内容变化就拒绝。
- 外部站点若不允许 FAL 抓图，桥接层会按 FAL 官方支持的 Data URI 方式内嵌已校验字节。
- GPT‑Image 1.5 的 `/edit` 端点以高保真模式保留真实结构，再重新画成透明像素资产。
- 验收 AI 同时看真实参考图和候选图，比较大结构关系；不会因为像素化省略微小照片细节就误拒，也不会因为“有参考图”而跳过任何身份门槛。

当前 81 杠参考来自 Wikimedia Commons 的博物馆照片，作者为 Tyg728，许可为 CC BY-SA 4.0。来源页、作者、许可证和参考图哈希都写进生成 manifest；派生图按该许可证留档。

## 当前边界

这四个型号已经有精确身份卡和通过门禁的缓存成品。其他枪械名称可以交给 AI 身份解析器，但只有在声明合法、图像身份足够明确并通过同样两道门禁后才能展示；系统不会因为名称陌生而拿通用枪图糊弄过去。左轮、管式或折管霰弹枪、弹链武器、发射器和载具仍需各自的结构轴与门禁。
