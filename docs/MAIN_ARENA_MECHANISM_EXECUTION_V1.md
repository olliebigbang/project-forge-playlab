# 通用武器机制接入主战场：执行与画面审核

日期：2026-08-30。工作分支：`codex/combat-mechanism-integration-v1`。

## 这轮实际完成什么

普通物品不再进入主战场后统一套用固定挥击计时器和近身圆圈。工坊/武器库交来的完整机制声明，现在通过同一个动作编译器和连击控制器执行。

- 点按：按编译结果连续使用第 1、2、3 段动作。
- 长按：进入物品的结构能力；蓄力释放会等待松手，持续能力会按住维持，开关型能力可保持展开状态。
- 起手、攻击、收招各有自己的时间和移动代价；闪避取消遵守编译后的窗口。
- 伤害、击退、硬直和接触类型使用当前这一段动作，不把第三段的钩回等能力套到所有攻击上。
- 吸血仍需要明确的吸血效果，不再给普通近战隐含回血。
- 人手、物品像素、接触位置来自同一帧。普通实体只在实际显示的有效接触像素附近命中；喷流等作用场使用同一多边形显示和判定。起手和收招不造成接触伤害。
- 三战界面显示连击段数与起手/出招/收招/能力状态。训练区也复用这个执行和渲染入口。

这些规则没有新增按“伞、锤、三节棍”等名字选择招式的分支，也没有让玩家指定握法或攻击方式。

独立审核代理直接看 Godot 渲染的原尺寸截图，第一次判定 NEEDS_WORK；修订后复审。

| 问题 | 通用处理 | 复审结论与证据 |

| 分节硬棍弯成软鞭 | 从已绑定的真实 Alpha 粗细变化识别连接节；硬段保持长度，仅连接处转动。没有可测细颈时不凭名称捏造节数 | PASS：`../.tools/melee-axis-review/visual-v4/replay-02-normal-1.png`、`-2.png`、`-3.png` |

| 拉长的黑色鱼线断续、暗墙上消失 | 对实际声明的鱼线按屏幕像素密度重采样并提高对比；这些像素也进入同一接触帧，不画另一条调试线冒充 | PASS：`../.tools/melee-axis-review/visual-v2/replay-07-normal-1.png`、`-3.png` |

这不是外聘画师的认证，也不是全动画高美术完成度认证；是独立代理对指定真实渲染采样帧的结构可读性复核。

## 逐轴执行证据

`tests/test_arena_mechanism_axes.gd` 使用同一匿名测试轮廓，每次只改一个轴，在适用的合法上下文执行三次点按和一次长按。输出保存了每段的最终动作参数、实际计时、位移、角度、接触像素范围和作用场。

完整机器证据：`../.tools/melee-axis-review/execution-matrix.json`。

| 轴 | 这次对照 | 实际观察的差别 |
| --- | --- | --- |
| 握柄长度 | 中→长 | 动作角度、位移、能力用时 |
| 主体长度 | 中→长 | 实际物体与接触范围 |
| 握持结构 | 单手柄→双手柄 | 出招时间、移动、握持位置 |
| 软硬 | 硬→半硬 | 有效攻击时长、动作和恢复 |
| 重量分布 | 居中→前重 | 时间、惯性相关位移、动作 |
| 主接触面 | 边缘→宽面 | 有效接触像素、角度与敌人反应 |
| 次接触面 | 无→尖端 | 第三段的动作与接触区域 |
| 主体柔性结构 | 弯曲杆→软线 | 动作路径、时长、接触位置 |
| 牵引段结构 | 软线→连接段 | 编译动作、时长与接触位置 |
| 末端负载 | 无→重 | 时长、末端相关位移与接触 |
| 缠钩方式 | 无→钩住 | 目标反应改为向玩家拉回；几何路径可以不变 |
| 软线展开 | 固定长→甩出收回 | 第三段和能力的端点距离、时长 |
| 状态结构 | 径向展开→伸缩 | 展开像素和作用范围 |
| 激活方式 | 瞬时→持续按住 | 能力维持时长 |
| 功能输出 | 接触→定向喷流 | 额外真实作用场及其命中范围 |

这 15 个选定对照均观察到作用，但不等于“所有值、所有组合均正交”。特别是：

- 软线轴需要有软线的合法上下文；状态轴需要可激活结构。条件不成立时零效应可能是正确结果。
- 次接触面测试关闭了会自动补尖端/宽面的结构标记，避免被已有覆盖逻辑掩盖。
- 钩回主要改变敌人反应，不要求改变动画轨迹；另有主战场测试验证真实第三段命中后的拉回。
- 本轮没有重新执行初始 commit `442fee3` 的全部 Clamp 矩阵、重复方向、五个布尔标记全覆盖，或 clean defaults/saved tuning 双套几何稳定性审计。不能借本轮结果宣称那些历史审计项目已经全部完成。
- 当前命中仍是离散时间采样、像素接触点和目标半径的近似，不是完整连续刚体碰撞模拟。

## 测试与实际渲染回放

统一入口：`scripts/test_complete_weapon_system.ps1`。该入口不读取 `.env`，清除在线生成凭证，使用隔离武器库。

最终总回归：**112 项通过，0 项失败**（Godot 11 组共 104 项，Python 候选桥接器 8 项）。日志与 `summary.json` 位于 `../.tools/system-tests/cea08cba81c94ccfaa6c0e3b1f374912/`。离线运行出现系统证书库警告；没有把它视为任何在线调用成功的证据。测试入口同时检查进程退出码、失败计数和脚本错误，不仅依赖退出码。

新覆盖包括：15 轴执行、可见像素与命中一致、无起手/收招/远处伤害、第三段次接触、真实鱼线端点、松手释放、训练区效果门禁、匿名两/三/四节结构长度不变、细线连续性和细长本体握持比例。既有存档、生成服务、枪械、敌人、关卡、目标反应继续回归。

三战机器人使用普通移动、攻击、闪避输入，远程保持距离，软体控制类靠近并调整站位；不靠修改敌人血量或玩家无敌过关。它们通过相同三场战斗，但只是可执行与可通关证据，不是平衡或玩家策略多样性的充分证明。

真实图形渲染入口：`tests/melee_review_session.tscn`，加 `-- --replay` 运行自动输入序列。渲染使用 Godot OpenGL 后端，不是生成示意图。最终截图和指标在：

- `../.tools/melee-axis-review/visual-final/`
- `../.tools/melee-axis-review/visual-final/visible-replay.json`

回放覆盖 9 个现有条目：两类折叠刀、短锤、分节棍、风扇、伞、伸缩杆、鱼竿、M4A1。普通物品使用现有 AI 缓存声明和真实图像重新校验后的条目；鱼竿是明确标记的开发样本，枪为现有缓存。没有申请付费新图，没有把失败缓存强行补成可用武器。每项执行约 7 秒的动作回放，不是 9 件武器分别完整三战通关。

最终回放的 9 项运行时错误均为空；普通物品每项发起 4 次动作，记录到 1–2 次接触命中，枪械记录到 20 发射击及一次换弹。三战机器人最终一组结果：远程剩余生命 21.3，软体控制类剩余生命 50.8。输入策略和武器不同、部分场景状态也有波动，不能拿这两个样本推断总体平衡。

性能记录是审核场景中 arena 更新耗时，不等于整帧耗时；存在首次变形/截图等尖峰，不据此宣称稳定 60 FPS。

## 尚未完成的验收和设计边界

**桌面手动试玩未完成。** 桌面控制工具明确拒绝对 Godot 的操作权限。本轮真实渲染回放与无界面机器人测试均有证据，但不能冒充亲自用键鼠在用户桌面试玩。需要开放相应权限后补验。

本轮完成的是“机制轴→主战场动作→命中与反应”的接入和指定结构可读性。还未完成全部初始 game design：一句话修改已有武器并继承身份、全面未知物品理解率、全部轴值/组合的独立性审计、玩家平衡测试，以及线上服务与发行准备均不能标为完成。

没有新增付费 AI 调用，没有删除玩家武器库，没有提交或推送本轮改动；保留了工作树中先前的系统开发和无关改动。
