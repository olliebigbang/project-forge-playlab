# 敌人数值测量 V2（多种子与有限续航）

日期：2026-09-03

> 这是2026-09-04改成“七只沿途怪＋一只守门者、每路标8秒”之前的耐久压力基线。
> 其中90秒路标、持续增援和约40～50只击败数不再描述当前主试玩；敌人单招测量仍可参考。

这套仪表用于回答“当前怪物到底有多危险、哪里造成伤害、怪多时是否变慢”。探针本身
不改敌人生命、伤害、预警、刷怪或武器数值；2026-09-03在三类精英技能接入后，用测量
结果做了一项生产调优：把单张连续地图每个路标的恢复从30生命/2补给收紧为10生命/1补给。
没有改敌人单招、血量、刷新上限或玩家武器。本轮没有调用在线AI，也没有读写个人武器库。

## 三层证据必须分开

1. **静态计算**：读取晴日敌人离线蓝图，经过正式攻击编译器，列出预警、有效段、恢复、单次伤害和理想最短循环下的名义每秒威胁。它不包含走位、攻击选择和玩家闪避。
2. **普通输入机器人**：只发送移动、短按攻击、闪避和补给输入。它不传送、不改血、不删怪、不加快路标。固定种子下分别使用一把枪、一把刚性长柄和一把柔性武器。
3. **真实 Godot 图形层**：非 headless 启动，实际渲染并保存截图，同时记录关卡更新耗时与整帧墙钟间隔。后者不是纯 GPU profiler，也不是桌面手动试玩。

运行入口：

```powershell
.\scripts\run_enemy_balance_probe_v1.ps1
```

默认使用种子7/14/29，每件武器最多跑900秒，并生成到
`.tools/enemy-balance-probe/<时间>/`：

- `multi-seed-normal-input-bot/report.json`：三个种子乘三把武器；每局单独重置随机状态。
- `real-gpu/report.json`：三把武器各 24 秒，并各保存两张实际画面。
- 两层分别保留 `stdout.log` 和 `stderr.log`。

报告字段中 `static_calculation`、`normal_input_bot`、`real_godot_render`、`desktop_manual_input`
会明确标记证据类型。一次运行没有完成关卡也仍然是有效测量结果，不会被伪装成“通过”。
V2另按基础攻击、回声、残留以及普通/机制精英攻击者分别归因，并把击杀寿命与限时仍存活
样本分开，避免把幸存者当作零秒击杀。

## 三类机制精英接入后的多种子调优（当前）

## 如何用于后续分工

- **怪物外皮**可以并行制作，但不得改变碰撞 Alpha、攻击时序或攻击根节点后仍沿用这份数值基线；更换后必须补真实截图和轮廓碰撞复核。
- **怪物技能**先以本仪表验证预警、有效段、来源归因和命中率，再谈增删招式。技能改动会改变玩家决策，优先级高于细调生命/伤害。
- **数值**最后依据至少多个种子、三类机制和玩家试玩再调。一次机器人通关或一次高命中率都不能单独成为改数值依据。

## 已知边界

- 当前调优有三个固定种子和一种机器人输入策略；样本仍不足以形成玩家胜率或难度置信区间。
- 没有桌面手动输入，没有主观可读性、乐趣或体感结论。
- 命中率以攻击进入有效段为分母；攻击在预警期被玩家武器打断不会进入分母，报告另保留 `attack_attempts`。
- `step_ms`只包围关卡更新。`render_frame_wall_ms`包含等待一帧的墙钟时间，不等于显卡单独耗时。
- 当前仪表读取随游戏打包的五件离线武器并自动挑选三个结构代表；不会打开个人武器库。
- 当前报告只用于建立基线，没有修改任何生产数值，也没有宣布怪物平衡已经完成。
