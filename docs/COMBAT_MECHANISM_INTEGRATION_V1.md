# 战斗机制整合 V1

## 现在接通了什么

这一版把两条已经完成的机制链真正接在一起：

1. 敌人攻击机制轴决定敌人怎样预警、何时锁定、攻击区域是什么、能否被打断以及攻击后的空档。
2. 玩家武器机制轴决定命中后造成伤害、推移、硬直、破甲、钉住、缠绕或压制。
3. 武器命中正在出招的敌人时，敌人的稳定性轴会判断这次反应是否足以打断当前阶段。

玩家不需要回答敌人应该怎样攻击，也不需要回答武器应该怎样打断敌人。

## 实际运行顺序

```text
敌人根据距离与纵深选择可用攻击
        ↓
telegraph 预警
        ↓
commit 锁定方向或落点
        ↓
active 使用同一份区域数据判定命中
        ↓
recovery 进入可反击空档
```

预警图形与真实命中区域共享同一个几何签名，不允许“地上画一套，实际打一套”。锁定发生后，冲锋不会偷偷继续追踪玩家。

## 武器怎样影响敌人出招

- 脆弱攻击：强硬直、钉住、缠绕等机制可以在预警或出招阶段打断。
- 普通可打断攻击：只允许在预警阶段被足够强的反应打断。
- 装甲蓄力攻击：预警阶段可以打断；进入 commit 或 active 后会按机制数据抵抗打断。
- 没达到门槛的轻微反应仍然造成伤害和视觉反馈，但不会伪造一次打断。
- 成功打断不会让敌人瞬间恢复行动，而是进入该攻击声明的 recovery 空档。

## 当前场景接入

- Slag Puppet 使用接触弧形攻击：持续追踪到 active，出招脆弱，攻击后有可惩罚空档。
- Forge Ram 使用锁定冲锋：commit 时锁定方向，蓄力后直线冲刺，commit 和 active 具有装甲稳定性，失败后有较长空档。
- 枪械战斗场景中的 Swarmling、Rusher 和 Guard 也使用同一运行驱动；枪械造成的破甲、硬直和压制会进入同一套打断判断。

这些名字只出现在场景内容适配层。通用编译器、选择器和运行驱动器不读取敌人名字。

## 验证边界

联合测试检查：

- 四阶段运行顺序；
- 锁定后不转向；
- 预警与命中共用几何；
- 现有敌人节点确实使用编译结果；
- 强控制打断脆弱预警；
- 弱反应不伪造打断；
- 装甲 commit 抵抗控制；
- 通用运行层没有敌人身份或玩家确认分支。
