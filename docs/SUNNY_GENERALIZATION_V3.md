# Sunny 任意物品泛化 V3

核对日期：2026-09-01。目标不是再补“灭火器、自拍杆、铅锤”等名字表，而是检查同一套
AI物理结构解析器能否面对不同种类的新文字，自动给出可执行的机制轴；玩家不选择怎么打。

## 白话结论

- **认识物品并编机制：本轮通过。** 冻结随机抽取12类输入，最终12/12语义结果满足各自的
  结构证据；11个可手持物产生11张不同机制卡，没有两张整卡重复。活猫被送去角色/怪物路线，
  没有被缩成手持武器。
- **自动画成可直接玩的武器：本轮没有通过成品门。** 只允许2次真实视觉管线。软线重锤图
  被自动软体轮廓门拒绝；伸缩自拍杆技术门通过并能隔离保存，但人工查看发现手机夹和手柄左右
  职责颠倒，自动握点会让人物抓错一端。因此两件都没有进入正式动作和三章试玩。
- 这不是“系统完全失败”：文本理解、机制差异和安全分流已经形成可复现证据；当前真正的短板
  从“认不认识任意物品”收窄为“生成图是否把已声明的握持部和作用部画在正确方向”。

## 通用规则改动

所有修正都围绕轴之间的物理关系，不读取样本名称：

- 字面描述若已经明确给出材料、部件、连接和形状，AI按这些结构评分，不强迫先知道商品名。
- 一根连续绳只占一条柔软路径；末端重物、夹子等不凭同义词再造第二根绳。
- 软线/链节/弯曲杆是比“软或硬”更具体的声明。存在具体柔性拓扑时，粗粒度刚性轴统一为
  `flexible`；反过来只说“柔软”却不给出哪里弯，仍然拒绝。
- 刚性物体没有柔性或挂绳路径时，末端负载、缠绕方式和放线方式只能是`none`。刚性夹具、
  头部或附件不会被误当成软线负载。
- 新视觉提示固定“握持部在画布左侧、接触/输出部在右侧”，需要反向时只能整件镜像，不能
  交换或重画部件。通用视觉缓存版本已升级，旧方向图不会自动命中新管线。
